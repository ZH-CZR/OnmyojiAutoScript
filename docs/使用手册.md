## 1. 使用前必读

1. **这是第三方辅助工具**，使用存在账号风险。请自行评估，风险自担。
2. 不要把脚本用于盈利、代练、工作室等场景。
3. 不建议在主力账号上长时间无人值守，尤其是新活动刚开放时。
4. 脚本依赖画面识别，**游戏 UI 改版会导致部分任务失效**，需要等资源更新。
5. 遇到问题先看第 14 章日志，再查第 15 章 FAQ。

- 支持模拟器和 Windows 桌面客户端。

## 3. 准备工作

### 3.1 系统

- Windows 10 / 11，64 位。
- 建议 8GB 以上内存；同时跑多个模拟器时 16GB 更稳。
- 安装路径**不要有中文、空格**，例如 `D:\OAS\`。

### 3.2 模拟器

推荐 MuMu 模拟器 12 或雷电模拟器。

必须设置：

1. **分辨率 1280×720（横屏）**。
   这是硬性要求，不是 1280×720 时脚本会直接报：
   `Please set emulator resolution to 1280x720`。
2. **DPI 240**（或默认）。
3. 开启 **ADB 调试**。
4. 关闭模拟器的「自动旋转屏幕」。
5. 使用 `window_background` 截图方式时，**模拟器窗口不能最小化**。

### 3.3 游戏

- 安装阴阳师官服/B 服客户端。
- 提前登录一次，记住账号密码（自动登录依赖游戏自身记住的账号）。
- 建议在游戏设置里关闭会频繁弹出的活动广告（能减少识别干扰）。

## 4. 安装

### 4.1 下载

从项目 Release 下载最新压缩包，解压到无中文、无空格的目录。

### 4.2 目录检查

解压后至少应包含：

```
oas.exe
console.bat
oas-backend.bat
deploy/launcher/oas-gui.bat   # 源码目录；发布包通常直接提供 oas.exe
requirements.txt
config/
module/
tasks/
```

> 缺少 `toolkit/`（便携 Python/Git/adb）时，首次启动安装器会自动补齐或用系统环境。

### 4.3 首次安装依赖

双击 `oas.exe`（发布包）或 `deploy\launcher\oas-gui.bat`（源码目录）。

启动脚本会先执行：

```powershell
python -m deploy.installer
```

安装器会检查并准备：

- Python 依赖（按 `requirements.txt`）
- Git
- adb
- uiautomator2

第一次会比较慢，属于正常现象。安装成功后会自动执行 `pythonw gui.py` 打开 GUI。

### 4.4 手动装依赖（可选）

如果自动安装失败，打开 `console.bat`，执行：

```powershell
python -m pip install -r requirements.txt
```

## 7. 新建和配置实例

一个「实例」= 一份配置 = `config/<名字>.json`。

### 7.1 新建

1. 打开界面，选择「新增」。
2. 输入实例名（建议英文，如 `oas1`、`main`）。
3. 基于模板 `config/template.json` 生成新配置。

### 7.2 复制

已有实例配置好后，可复制一份给第二个模拟器/账号，只需改 Serial。

### 7.3 命名建议

- 一台模拟器一个实例：`mumu1`、`ld1`。
- 不要用中文和特殊字符，避免路径与日志问题。

### 7.4 配置文件结构（了解即可）

```json
{
  "config_name": "oas",
  "script": { "device": {...}, "error": {...}, "optimization": {...} },
  "restart": {...},
  "global_game": {...},
  "orochi": { "scheduler": {...}, "orochi_config": {...} }
}
```

- 改任何配置项都会**自动保存**，不需要点保存按钮。
- 想批量改，建议先备份 JSON。

## 8. 模拟器设置（最关键的一步）

位置：`脚本 → Script → 模拟器`。

### 8.1 Serial（设备地址）

- `auto`：自动检测（推荐只有一个模拟器时使用）。
- 多个模拟器同时开时，`auto` 会失效，必须手填。

常见默认值：

| 模拟器 | Serial |
| --- | --- |
| MuMu 模拟器 12 | `127.0.0.1:16384` |
| MuMu 模拟器（旧） | `127.0.0.1:7555` |
| 雷电模拟器（全系列） | `emulator-5554` 或 `127.0.0.1:5555` |

多开时 Serial 会变，可在 `console.bat` 里执行下面的命令查询：

```powershell
adb devices
```

### 8.2 句柄 Handle

- 留空：不使用窗口操作。
- `auto`：自动检测。
- 也可填窗口标题或句柄号。

常见标题：

| 模拟器 | 句柄标题 |
| --- | --- |
| MuMu 模拟器 12 | `MuMu模拟器12` |
| MuMu 模拟器 | `MuMu模拟器` |
| 雷电模拟器 | `雷电模拟器` |

> MuMu 多开时窗口标题可能相同，需要手动填句柄号。

### 8.3 截图方式

`截图方式` 可选 `auto` 或手动指定。速度排序（官方帮助）：

```
window_background >>> DroidCast_raw > ADB_nc >> DroidCast > uiautomator2 ~= ADB
```

| 方式 | 特点 |
| --- | --- |
| `window_background` | 最快（约 10ms），但**模拟器不能最小化**，且依赖窗口句柄 |
| `DroidCast_raw` | 较快（约 100ms） |
| `ADB_nc` | 中等 |
| `DroidCast` | 中等偏慢 |
| `uiautomator2` / `ADB` | 最慢，但兼容性最好 |

新手建议：先 `auto`；如果识别不到画面，改成 `DroidCast_raw` 或 `ADB`。

### 8.4 控制方式

速度排序：

```
window_message ~= minitouch > Hermit >>> uiautomator2 ~= ADB
```

- `minitouch`：默认，速度快，推荐。
- `window_message`：最快之一，但**偶尔会失效**，且需要句柄。
- `Hermit`：速度介于 minitouch 与 uiautomator2 之间，可作为备选。
- `uiautomator2` / `ADB`：慢但稳，兼容性好。

### 8.5 其他设备项

| 配置 | 说明 |
| --- | --- |
| `adb_restart` | 检测不到设备时尝试重启 adb |
| `package_name` | 装了多个客户端时指定包名（如官服/B 服） |
| `emulatorinfo_*` | 模拟器信息，用于自动启动/关闭 |
| `emulator_window_minimize` | 允许最小化（与 window 截图冲突，慎开） |
| `run_background_only` | 仅后台运行 |

### 8.6 桌面客户端模式

位置：`Script → Script → 桌面`（`script.desktop`）。

| 配置 | 说明 |
| --- | --- |
| `enable` | 启用桌面客户端模式 |
| `game_path` | 游戏 exe 路径 |
| `profile_dir` | 客户端数据目录 |
| `window_pos` | 窗口位置 |
| `window_title` | 窗口标题（用于绑定） |
| `launch_instance` | 是否由脚本启动客户端 |

启用后：

- 截图固定为 `window_background`
- 控制固定为 `window_message`
- 客户端未登录时，调度器会先执行 `Restart` 任务

## 9. 脚本通用设置

位置：`脚本 → Script`。

### 9.1 出错（`script.error`）

| 配置 | 默认 | 说明 |
| --- | --- | --- |
| `handle_error` | 开 | 处理部分异常，出错时撤退 |
| `error_repeated` | 关 | 连续出错时关闭模拟器 |
| `save_error` | 开 | 出错时保存日志和截图 |
| `screenshot_length` | 1 | 保留最后 X 张截图 |
| `notify_enable` | 关 | 启用消息推送 |
| `notify_config` | - | onepush 的 YAML 配置 |

推送配置示例（onepush）：

```yaml
provider: telegram
token: 123456:ABCDEF
userid: 123456789
```

### 9.2 优化（`script.optimization`）

| 配置 | 默认 | 说明 |
| --- | --- | --- |
| `screenshot_interval` | 0.3 | 两次截图最小间隔，范围 0.1～0.3，降低 CPU |
| `combat_screenshot_interval` | 1.0 | 战斗中截图间隔，范围 0.1～1.0 |
| `task_hoarding_duration` | 0 | 囤积任务 X 分钟后再一起执行 |
| `when_task_queue_empty` | `goto_main` | 队列空了做什么：回庭院/关游戏/关模拟器 |
| `close_game_limit_time` | 00:30:00 | 关游戏前的等待上限 |
| `close_emulator_limit_time` | 00:30:00 | 关模拟器前的等待上限 |
| `emulator_startup_lead_time` | 00:02:00 | 模拟器启动预留时间 |
| `schedule_rule` | `Filter` | 调度规则 |

调度规则说明：

- `Filter`（默认）：按开发时确定的顺序，一般是最优解。
- `FIFO`：按下次执行时间排序，先到期先跑。
- `Priority`：优先级高的先跑，同级先来后到。

### 9.3 全局游戏（`GlobalGame`）

| 配置 | 默认 | 说明 |
| --- | --- | --- |
| 当出现协作邀请时 | `accept` | 默认全部接受 |
| 检测间隔 | 10 秒 | 多久检查一次协作邀请 |
| 网络异常时 | 等待 10 秒 | 不立即重启 |
| 网络出错需重连 | 重启游戏 | 断线处理策略 |
| 庭院客户端清空缓存 | 开 | 处理进入庭院要求清理缓存的弹窗 |

### 9.4 重启（`Restart`）

| 配置 | 说明 |
| --- | --- |
| `enable_daily` | 每天定时重启游戏 |
| `next_run` | 重启任务的下次时间 |
| `server_update` | 服务器维护时间（默认 09:05） |
| 角色名 | 多角色账号时指定登录角色 |

> 维护日请把 `server_update` 设置为实际开服时间，避免任务在维护期间反复失败。

## 10. 任务配置的通用四件套

每个任务顶部都有「任务调度」：

| 配置 | 说明 |
| --- | --- |
| `enable` | 是否加入调度器。不开就永远不会自动跑 |
| `next_run` | 下次运行时间。**清空后回车 = 立即** |
| `priority` | 优先级 1～15，数字越小越优先（仅 Priority 规则生效） |
| `success_interval` | 成功后间隔，格式 `[天] [时]:[分]:[秒]`，如 `01 00:00:00` |
| `failure_interval` | 失败后间隔，格式同上 |
| `server_update` | 强制设定每天的执行时间，非 `09:00:00` 时生效 |
| `delay_date` | 延迟天数 1～31 |
| `float_time` | 随机浮动时间 |

常见写法：

| 需求 | 配置 |
| --- | --- |
| 每天跑一次 | `success_interval = 01 00:00:00` |
| 每 6 小时跑一次 | `success_interval = 00 06:00:00` |
| 每天 9 点跑 | `server_update = 09:00:00` |
| 失败了 10 分钟后再试 | `failure_interval = 00 00:10:00` |
| 立刻跑一次 | 清空 `next_run` 回车 |

> 时间格式写错不会报错，但不会按预期执行。注意用英文冒号。

## 11. 怎么排「一条龙」

OAS 没有单独的「一条龙」开关，它的「一条龙」就是**把所有任务的调度器串起来**：

1. 每个任务设置 `enable = true`；
2. 设置各自的 `success_interval` / `failure_interval`；
3. 调度器自动挑出到期的任务按顺序执行；
4. 全部跑完后，等待下一个到期任务。

一个典型的日常排班示例：

| 时间 | 任务 | 间隔设置 |
| --- | --- | --- |
| 每天 08:30 | 重启/登录 | `server_update = 08:30:00` |
| 每天 09:10 | 悬赏封印 | 成功 1 天 |
| 每天 09:30 | 每日琐事 | 成功 1 天 |
| 每天 10:00 | 御魂（八岐大蛇） | 成功 1 天 |
| 每天 17:00 | 封魔之时 | 成功 1 天 |
| 每天 19:00 | 道馆 | 成功 1 天 |
| 每周一 09:00 | 真·八岐大蛇 | 成功 7 天 |
| 每周一 09:30 | 秘闻 | 成功 7 天 |

要点：

- 需要「先登录再跑任务」时，把 `Restart` 的 `server_update` 设得比第一个任务早 5～10 分钟。
- 想减少模拟器起停，开 `task_hoarding_duration`（例如 10 分钟）。
- 想让任务按固定顺序跑，保持默认 `Filter`，不要用 `FIFO`。

## 13. 运行、监控与停止

### 13.1 启动

1. 打开模拟器，进入游戏，停在任意稳定界面（推荐庭院）。
2. 确认实例的 Serial 正确。
3. 在界面点「启动」。
4. 观察「任务总览」：能看到当前任务、下次任务、运行状态。

### 13.2 运行中你会看到什么

- 日志区滚动：`Scheduler: Start task ...`、`TaskEnd` 等。
- 任务总览里状态在 `pending` / `running` / `waiting` 之间切换。
- 出错时会自动截图并保存到 `log/error/`。

### 13.3 停止

- 界面点「停止」。
- 紧急情况：直接关闭模拟器，脚本会进入重试/退出流程。
- 停止后建议等几秒再启动，避免端口未释放。

### 13.4 什么时候该手动干预

| 情况 | 建议 |
| --- | --- |
| 活动首次开放、UI 变化 | 先手动跑一次，确认识别正常 |
| 频繁卡在同一画面 | 停脚本，看错误截图 |
| 账号有异常登录提醒 | 立即停止并检查 |
| 服务器维护 | 停脚本，改 `server_update` |

## 14. 日志与出错现场

### 14.1 位置

| 内容 | 路径 |
| --- | --- |
| 运行日志 | `log/` |
| 错误截图 + 日志片段 | `log/error/<脚本名>_<时间>/` |

错误目录里通常有：

- 若干张 `*.png`（最后几张截图）
- `log.txt`（从上一个任务分隔线到出错位置的日志）
- `diagnosis.json`（中文诊断：错误结论、处理建议、时间线、环境与配置快照，≤64KB）

### 14.2 怎么看

1. 先看 `diagnosis.json` 里的 `error.summary`（发生了什么）和 `error.suggestion`（该怎么办）。
2. 再看 `log.txt` 最后 20 行，找 `ERROR` / `CRITICAL`。
3. 最后看最后一张截图，确认画面停在哪。
4. 对照 FAQ 判断是设备问题、识别问题还是游戏问题。

> 诊断包按自用需求保留明文配置与日志，不要上传到公开网络。

### 14.3 日志级别

- `INFO`：正常流程。
- `WARNING`：可恢复的小问题。
- `ERROR`：任务出错。
- `CRITICAL`：环境或设备致命问题（如分辨率不对）。

## 15. 常见问题 FAQ

### Q1：启动就报 `Please set emulator resolution to 1280x720`

模拟器分辨率不是 1280×720（横屏）。到模拟器设置里改成 1280×720、DPI 240，重启模拟器。

### Q2：提示检测不到设备

1. 确认模拟器已开启 ADB 调试。
2. `console.bat` 里执行 `adb devices`，看有没有设备。
3. 多个模拟器时不要用 `auto`，手填 Serial。
4. 打开「在检测不到设备的时候尝试重启 adb」。

### Q3：能看到截图，但点不动

1. 控制方式改成 `minitouch` 或 `uiautomator2`。
2. 用 `window_message` 时需要正确句柄，且可能偶发失效。
3. 确认模拟器没有被其他程序占用输入。

### Q4：截图全黑 / 卡住不动

1. 截图方式换 `DroidCast_raw` 或 `ADB`。
2. 用 `window_background` 时**不能最小化**模拟器。
3. 检查是否开了「仅后台运行」但模拟器不支持。

### Q5：任务一直不执行

检查三件事：

1. 该任务的 `enable` 是否为开；
2. `next_run` 是否已到期（清空回车可设为当前）；
3. 时间格式是否用了英文冒号。

### Q6：任务顺序不符合预期

`优化 → 调度规则`：

- 想按开发预设顺序：`Filter`；
- 想按到期时间：`FIFO`；
- 想按优先级：`Priority`（数字小的先跑）。

### Q7：启动提示端口被占用（22268 / 22269 / 22288）

同时开了两个 OAS 实例。解决：

1. 只保留一个实例运行；
2. 或修改 `config/deploy.yaml` 里的 `OcrServerPort`、`ImageServerPort`、`WebuiPort`，每个实例用不同端口。

### Q8：任务失败了，但游戏画面看起来正常

1. 看 `log/error/` 的截图，通常是某个弹窗没被识别；
2. 降低对应资源的阈值不是长久之计，建议等资源更新或反馈 issue；
3. 临时处理：手动关掉弹窗后重新启动。

### Q9：维护期间一直失败

把 `Restart` 的 `server_update` 改成实际开服时间；维护期间停止脚本。

### Q10：CPU 占用很高

1. `screenshot_interval` 设为 0.3；
2. `combat_screenshot_interval` 设为 1.0；
3. 队列空时关闭游戏或模拟器；
4. 降低模拟器帧率/分辨率（保持 1280×720）。

### Q11：协作邀请一直弹

`GlobalGame → 突发检测 → 当出现协作邀请时`，选择接受/拒绝策略。默认全部接受。

### Q12：自动登录失败

1. 手动登录一次，让客户端记住账号；
2. 多角色账号填写「角色名」；
3. 桌面模式确认 `game_path`、`profile_dir` 正确。

### Q13：配置丢了/换电脑了

- 配置都在 `config/*.json`，复制整个 `config/` 目录即可迁移。
- 界面支持导入/导出配置（导出会脱敏）。
- 换电脑前先停止脚本，避免写入中断。

### Q14：更新后任务全失效

游戏 UI 改版导致资源过期。等待项目更新资源，或回滚到上一个可用版本。

### Q15：能用命令行跑吗

可以，但一般不需要。调试用：

```powershell
python script.py
```

注意脚本里的配置名是写死的，需要按实际实例修改。

## 16. 数据备份、迁移与多开

### 16.1 备份

需要备份的只有：

```
config/        # 所有实例配置
log/           # 可选，排查问题时保留
```

`toolkit/`、`oas.exe` 等运行产物不需要备份。

### 16.2 迁移

1. 新机器装好 OAS；
2. 把旧机器的 `config/` 覆盖到新机器；
3. 检查每个实例的 Serial、句柄、截图/控制方式（新机器可能不同）。

### 16.3 多开

- 一台机器多个模拟器 → 多个实例，每个实例独立 Serial。
- 同一台机器同时运行多个 OAS 实例 → 端口会冲突，需要改 `deploy.yaml` 端口。
- CPU/内存不足时，减少同时运行数量，或错开任务时间。

## 17. 更新与回滚

### 17.1 更新

- 界面「更新」按钮；
- 或重新下载 Release 覆盖（保留 `config/`）。

### 17.2 回滚

1. 保留旧版本目录；
2. 出问题时把旧版本目录换回来；
3. 配置通常向下兼容，但新版本新增字段在旧版本会忽略。

### 17.3 更新前建议

- 备份 `config/`；
- 暂停所有任务；
- 记录当前可用版本号。

## 18. 安全与合规

1. 不要把账号密码写进配置文件或截图里分享。
2. 出错截图中可能包含昵称、聊天等信息，反馈前先打码。
3. 不要使用来源不明的「魔改版」「加速版」，可能带木马。
4. 仅从官方仓库/Release 下载。
5. 遵守游戏用户协议，风险自担。
