# 运行稳定性与配置一致性优化

本轮优化针对离线审查已确认的故障场景，不改变游戏任务的目标、奖励完成条件或资源限制。

## 配置保存与热更新

`ConfigModel` 保存加载或上次成功保存时的序列化快照。显式保存仅将本实例实际改变的字段合并到磁盘最新 JSON；读取、合并与原子写入共用同一个跨进程文件锁。不同任务、同一配置组的不同字段及未识别的旧字段互不覆盖。同一字段由最后一次实际修改该字段的写入决定；列表按完整字段更新。普通查询、`running_task` 和没有字段变化的重复保存不写盘。

空闲监听使用设备号、文件身份、纳秒修改时间和文件大小，按“不相等”判断变化。基准取自模型读取之前，因此同秒保存、原子替换、时间戳回退和读取后进入等待前的保存均能唤醒调度。新建任务配置对象时，共享设备同步绑定新对象；设备序列号、已连接设备和进程级低配模式仍需停止配置后重新启动。

## 任务故障恢复

- 道馆临时导航关系在整个任务流程的 `finally` 中恢复，保留原有额外边与按钮对象；反复换御魂不覆盖最初快照。任务成功、异常及退出都执行幂等清理。
- 道馆普通/未知馆内阶段无进展上限为 60 秒，已确认的集结、冷却及馆主等待等阶段为 300 秒；不再每 50 秒清空卡死计时，内层战斗仍沿用原有检测。
- 棋局保留设备卡死检测，同一回目首次确认的新阶段才重置独立的 300 秒进展预算。画面仍有标记但长时间没有变化，也必须进入异常恢复；作息守卫产生的主动休息扣除，原设备计时器在 finally 中恢复。
- 棋局购买经验以新截图确认阶段、按钮、倒计时和预算。一次点击后仅等待金币变化，未确认扣款期间不重复点击，阶段切换后不继续旧动作。扣款不明时本回目可能少买一次经验，下一回目重新检查预算。

## 图像与 OCR RPC

`ImageServerHost`、`OcrServerHost` 默认均为 `127.0.0.1`。本机使用无需改变用户配置；需要其他机器访问时才显式配置监听地址，并限制可访问该端口的设备。HTTP 的监听地址不影响 RPC 的监听地址。

图像帧、模板和 OCR 请求使用有大小限制的数字数组协议，不再反序列化 pickle。升级后需要同时重启后端及任务配置，使客户端和 RPC 服务使用同一协议；其他目录中运行的旧 RPC 服务不能直接混用。

双方通过 `get_server_info().image_protocol` 确认协议版本 `oas-image-v1`。不兼容时报告明确的更新/重启原因并关闭客户端连接，不向旧服务发送新格式数据。

日志归属保留完整配置名，包括下划线。设置操作日志只记录字段路径，API 请求、查询、响应和错误日志对敏感值脱敏。

## 功能边界

真实任务边界定义在 `module/config/capabilities.py`。百鬼夜行保留公开配置模型以读取旧配置，但从菜单、定时/手动/闲时队列和执行入口隔离；旧客户端请求立即执行会收到原因。现有字节码封装不在正常调度或菜单导入路径中执行，等待公开实现后再单独接入。当前工作树没有 `module/compat/`，不得将历史文档中的路径作为已实现功能。

## 离线验证

新增回归覆盖配置旧快照、多线程和真实 spawn 进程并发保存、同秒与反向时间戳、设备配置重绑、任务边界、道馆导航清理、棋局冻结与阶段切换、RPC 协议拒绝非法数据及日志脱敏。

对应新增模块为 `test_config_consistency`、`test_capabilities`、`test_dokan_runtime_safety`、`test_chess_runtime_safety`、`test_rpc_image_wire` 和 `test_log_privacy`。

```powershell
.venv\Scripts\python.exe -m unittest discover -s dev_tools -p "test_*.py" -q
.venv\Scripts\python.exe dev_tools/check_i18n.py
.venv\Scripts\python.exe -m pip check
```

上述检查不连接设备或运行游戏。真实 OCR、网络连接和游戏长时间运行需要另行实测。
