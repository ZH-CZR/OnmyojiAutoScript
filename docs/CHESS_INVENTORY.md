# 百鬼棋局持有量、星级及棋盘身份

## 规则与配置

铜色勾玉为一星、银色为二星、金色为三星。三张一星合成一张二星，
三张二星合成一张三星；一、二、三星分别折算1、3、9张一星。
实际卡片数与折算张数分开记录，不以历史累计购买数冒充当前持有量。

所有既有阵容默认追三星。新阵容可在 `shikigami_positions` 内使用字典格式：

```python
'薰': {'weight': 1, 'position': 2, 'souls': ('魍魉之匣',), 'target_star': 2},
'白狼': {'weight': 1, 'position': 4, 'target_star': 3},
```

`target_star` 只接受整数1、2、3，省略默认3。旧站位及御魂元组继续兼容，
不要把目标星级写入旧四元组的守护之印字段。本次没有新增前端配置入口。

## 持有量与购买、出售

`runtime/inventory.py` 保存单局账本，`runtime/card_tracking.py` 接入真实任务。
日志“棋局持有快照”包含各式神实际卡片数、各星级数量、折算张数，
以及1至12号位的名称、星级、特殊单位和星级确认状态。数据仅驻留内存，
每局重建，不写用户配置或闲时数据库。

备阶段关闭商店后，以稳定新帧核对手牌和全部棋盘位置。商店购买成功后
折算张数加一，合成不改变折算量；每轮买卡重新观察手牌。达到目标所需
张数后跳过同名商店卡，同一商店内连续出现多张也逐张重检。
赠送、复制等来源通过实际手牌与备阶段全量核对纳入，不要求来自商店。
只接入这些额外卡的识别及处理，没有新增主动使用复制札的策略。

已有另一张实际达到目标星级的同名卡时，多余手牌才可出售；优先保留
高星、场上卡及同星最左侧手牌。仅有足量但尚未合成的材料不会被出售，
唯一的目标成品不会被出售。出售需稳定新帧确认该名称和星级的卡恰好
减少一张；结果未明立即停止，不重复拖动。

购买后可按守恒量推断已知场上单位的合成升级，但这种推断单独标记为
尚未图像确认，不能独立作为出售其他卡的依据。备阶段重新读勾玉确认。
无法识别星级、买入结果或稳定画面时保留不确定状态；涉及的卡停止
购入。缺少人物素材的普通式神手牌先按下文规则清理，不能直接卡住
整个购买流程；仍无法排除阵容/特殊卡时保留并等待确认。
六阶前允许暂存未知棋盘身份，已确认阵容手牌继续买入/部署；
六阶起必须先完成未知单位恢复，才恢复新购买。

## 棋盘身份恢复

手动上阵前在备战区确认名称与星级，成功确认落位后才记录棋盘身份。
上／下阵只改变位置，不增加或扣除持有量。同名手牌优先部署高星；
场上低星而备战区已有更高星时，先回收旧卡再重新部署。

准备开始时检查全部12格。六阶前只登记未知占位，不主动逐个回收；
自然商店有阵容所需牌仍正常购买、按指定位置上阵。指定格被未知单位
占据时先回收该单位；目标格空但人口已满时，只回收一个未知单位腾位。
不回收已确认的其他阵容单位。回收后重新识别手牌坐标，再拖到指定格。
账本以 `deferred_board` 显式标记未完成核对，已确认购入量不会因系统
自动上阵而被清零；六阶全量核对后恢复真实持有量。

六阶起，自动上阵或身份、星级不确定的单位逐个回收到备战区；同时
确认原位置清空及备战区折算张数增加，随后重新识别和手动上阵。
非阵容式神手牌不受阶数及前三回合布局限制，备/战阶段均按调用阶段
清理，不等六阶才卖。六阶前不主动回收的约束仅针对棋盘未知单位。
河童等阵容替代卡保留各自规则。
回收途中也可出售已识别的非阵容手牌，为下一次回收释放备战区空间；
此时不依据尚未完整的库存出售阵容卡。回收失败、手满、识别不明或剩余时间不足时保留
未知状态，不按空位继续部署。仍沿用固定阵容，不部署非阵容式神。
已知单位的勾玉暂时漏识别时保留原记录和持有量，暂停新购买，不能
仅凭占位图标消失便扣库存、重复买入。

荒川右侧未知单位先打开详情排除金鱼；召唤物独立登记，不计持有量，
不当普通卡回收、出售。金鱼移动发生交换时同步记录被换位式神。

所有新操作检查备／战阶段、回目、符咒弹窗和剩余时间。普通动作预留
6秒，下阵预留8秒，特殊单位详情识别预留10秒；跨回目不续做旧动作。
“购买经验”正常按钮消失时不采纳持有快照，避免把拖动出售界面中
临时缩小或抬起的手牌误当作卡片消失。
不改变整局计数、满币、保段位及闲时让位语义，不取消设备卡死检测。

## 缺少人物素材的非阵容手牌

星级勾玉可独立定位缺人物素材的普通式神手牌。未知记录使用完整卡框
及卡片中心，不能用勾玉所在的1×1区域做阵容保护或直接拖动。
库存核对/商店手牌刷新遇到这类卡时，先排除低阈值多尺度阵容模板
（包括河童替补）、御魂、守护之印、纹章、发现御魂/纹章等特殊牌；
只有可排除上述类型的普通式神卡才出售。连续三帧确认星级、手牌数量、
位置及卡面稳定，耗时识别后出售前重新检查阶段、回目和同一卡面。
出售后以两帧手牌签名确认恰好少一张；失败不重拖、不将库存记为就绪。
同一卡面重复确认不重复执行昂贵的全套装备/OCR保护。

回收未知棋盘单位时，可先以确定星级的手牌折算量及原格清空确认下阵，
再清理回收到备战区的缺素材非阵容卡；不要求事先猜出它的名字。
无需为本身不属于阵容的缺素材卡新增人物图片。

## 验证与限制

`dev_tools.test_chess_inventory` 覆盖三合一、购入上限、赠送多余卡、
成品与材料保护、未知状态、交易未确认、12格恢复、阶段/回目中断、
默认与自定义星级，以及金鱼与普通单位的区分及换位记录。
与原棋局商店、运行安全、闲时、退出、任务/服务启动测试共同回归。
`dev_tools.test_chess_unlisted_hand` 覆盖缺素材清理后恢复河童购买、
前三回合非阵容清理、替补和装备保护、卡面/位置/阶段变化及未确认交易。
2026-11-09用户第三回合截图离线回放：原库存未就绪；模拟出售非阵容卡
后库存就绪，河童识别为 `kappa`、持有目标允许购买、17金币可负担1金币。
出售动作用桩模拟，未向游戏发送点击或拖动，不代表游戏流程实测通过。
帧缓存、并行识别与拖动提速的实现和离线基准见 `docs/CHESS_PERFORMANCE.md`。

星级识别复用现有铜/银/金勾玉素材，手牌按缩放匹配。用户提供的真实
截图用于铜色手牌识别检查；银色、金色的模板识别有离线验证，仍需
实战确认不同动画、遮挡和卡片重排下的稳定性。没有启动游戏。
