# 最后一只好友鬼王结算后转召唤

好友战斗已离开胜负/奖励画面，确认详情“结算中”后，不要求左侧好友卡片仍然存在。
挑战按钮隐藏时，指定好友头像或鬼王详情标志均可辅助确认。卡片消失不能让流程继续
等待结算，也不能阻止重新进入详情交还后续准备流程；仍在战斗时不提前切换。

优先检查其他可见的合格好友。没有其他合格目标时，直接点击“自己发现”，确认金框
选中后按实际门票选择规则召唤一只，不等待最后一只好友完成结算。自己的卡片被头像
占用且好友计时条已消失时，已确认的详情标志仍允许点击原自己发现区域。

普通执行和任务结束后的驻留均适用。驻留的转召唤属于新的明确例外，不需要当前还有
存活的好友；普通无好友观察仍不凭空召唤。已确认无票时不每5秒重复打开队列；新一轮
驻留会重新读取，余票布尔标记继续只来自实际选票面板、不写配置。无票则继续等待或
将执行权交还到期任务，不重新标记普通任务完成或改写其计划。

召唤及自己的鬼王进攻仍复用星级/名称、阵容/预设、追击与疲劳策略。召唤后仍存活的
自己发现鬼王可继续挑战，不重复召唤或重置该只进攻次数。原全局作息及疲劳已满时的
等待/喝茶规则保留；召唤及挑战发布实际运行状态并计入ActivityGuard，异常时清理状态。

实现涉及script_task.py的详情确认、resident.py的末只好友转召唤，以及friend_assist.py
的自己发现点击兜底。新增dev_tools.test_meta_demon_friend_settlement_tickets覆盖最后
卡片消失、隐藏挑战按钮、战斗保护、返回有鬼王的自己发现、驻留有票/无票、其他好友
优先、疲劳、继续自己的鬼王及异常清理。未启动游戏，实际页面响应仍待实测。
