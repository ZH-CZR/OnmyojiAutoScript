# 运行约束、点击时间与结算连点

这些功能用于控制运行量和输入行为，不代表已验证的防检测或防封保证。所有已有用户配置都保留，普通启动不自动改写配置文件。

## 作息和记账

`tasks/Script/config_antiban.py` 的 `enable` 默认关闭，控制睡眠窗口、累计运行后长休息和每日任务运行上限。

- `daily_active_limit` 保留旧含义：累计任务执行时间达到阈值后，按 `long_rest_duration` 长休息，然后重新累计。它不是每日上限。两者为零时不触发该长休息。
- 新增 `daily_runtime_limit`：默认零（关闭）。达到后在安全检查点暂停到本地日期次日，并继续检查睡眠窗口。长休息不会清零每日累计。
- `script.device.continuous_task_rest_enable` 独立于作息开关，默认关闭。按 `continuous_task_rest_interval` 抽取触发间隔，通常休息2至8分钟，少量8至20分钟。进入调度空闲状态重置连续运行计时；普通任务切换不重置。

`module/script/activity_guard.py` 在任务执行前后及执行中的设备截图处记账。运行中两次记账至少间隔5秒，任务正常结束、抛出异常或 `TaskEnd` 时强制结算。用单调时钟计算耗时，跨本地午夜按时段分配到两个日期；休息和调度空闲不计入任务执行时间。发生系统时间调整时，以单调耗时为准，日期分配仍取本地时钟。

每日累计、累计长休息计时及其休息截止时间保存到 `config/activity/runtime.sqlite3`，按配置名称隔离，用 SQLite 事务更新；该目录已忽略，不提交运行数据。进程重启不会清零。不同配置、重命名后的新名称独立统计，不是跨配置的账号在线总时长。连续任务随机休息计时仅在当前进程保留。

强制终止进程可能丢失最后一次记账后的耗时；5秒是截图记账的节流间隔，并非硬性后台刷盘周期。长时间没有截图的代码或阻塞调用，只有返回后才能记账。数据库不可读写时不以零计数继续运行，而是进入现有错误处理。

## 长任务检查点

`BaseTaskParent.screenshot()` 仅在守卫请求暂停、并识别到白名单中的胜败或奖励结算标记时执行等待；不在战斗中因达到时间阈值而强行退出。白名单包含共用胜败、奖励、贪吃鬼、统计，以及任务对应的胜败/奖励和探索统计标记。通过公共截图入口执行的御魂、通用战斗和探索结算可在单个任务内部暂停。探索另在已识别的大世界、章节入口和探索主场景调用显式检查点。

暂停不发游戏输入，不关闭游戏或模拟器，也不释放当前任务的设备所有权。组队队友可能自行开始下一轮；脚本仅暂停自己的输入，不保证游戏世界静止。按1秒片段等待，检查配置重载事件与配置文件修改时间（当前服务未传入共享重载事件），重新加载已保存设置；现有前端停止仍由进程终止实现。恢复时重置卡死计时和图像缓存并重新截图；卡死检测始终保留。

只直接调用设备截图、使用独立战斗流程且没有共用结算标记的路径，不自动获得任务内暂停；仍受新任务开始前的约束。任务原有次数限制、墙钟运行时限和队友等待时限保留，因此长暂停结束后可能按原限制结束任务，不保证续满次数。未新增自动离队、退回庭院或游戏内验证处理。

## 点击时间

新增独立开关 `click_timing_enable`，默认开启，不依赖作息总开关。公共 `Control.click()` 执行前等待0.06至0.18秒；minitouch 普通点击在按下和抬起之间显式等待40至110毫秒。ADB、uiautomator2、窗口后端保留各自的按压实现。长按、滑动不改变，直接调用底层输入方法的特殊流程不自动附加公共等待。

这只是有限的时间变化，不声称模拟真人的完整反应模型。现有识别、动画等待和重复操作限流继续生效。

## 结算连点与寮突破延迟

新增独立开关 `settlement_burst_enable`，默认开启。公共 `settlement_random_click()` 有15%概率生成2至3次点击，其余单击；关闭开关后始终单击。只有带 `SETTLEMENT_RANDOM_CLICK` 标记的动作可使用该功能，硬上限3次，长按和普通任务动作不连点。

第一次点击前保存当前可见的结算标记。每次追加点击前等待0.1至0.2秒（另有截图、后端和公共点击耗时），重新截图，并确认原结算标记仍存在；标记消失立即停止。每次重新采样坐标，连点结束后才重置外层操作间隔。不能识别结算画面时只单击。特殊任务未使用公共结算动作时不自动连点。

寮突破 `random_delay` 恢复实际执行：每次正式进攻前按 `random_delay_interval` 随机等待整数秒，等待后重新截图、检查区域可用性再操作。区间格式为“最小秒数,最大秒数”，默认 `2,10` 兼容旧配置；仅接受非负整数且最小值不大于最大值，两值相同为固定延迟，`0,0` 为不等待。不开启该选项不额外等待。战斗随机操作概率仍是每次调用 `4/501`（约0.8%），修正注释，不改变原概率或开关默认值。
