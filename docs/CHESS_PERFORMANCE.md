# 百鬼棋局操作提速

提速仅影响棋局任务，不改其他任务配置、不关闭设备卡死检测。

- 任务执行期间将设备截图最小间隔临时设为0.1秒。正常退出、异常及
  闲时让位均在 finally 恢复原间隔快照，不改其他任务配置。
- `runtime/performance.py` 按设备帧号与截图对象身份缓存纯识别结果，包含
  回目、阶段、阶数、金币、倒计时、占位、勾玉星级和手牌。新截图立即失效；
  无帧号时不缓存。不会缓存动作允许状态或跳过交易后截图。
- 手牌人物仅加载当前阵容及替补的模板，分类、库存、部署、清理和
  身份计数均复用此集合；切换阵容时同时清除模板和帧缓存。其他式神
  不逐个匹配，直接按勾玉定位后走非阵容清理保护流程。
- 手牌人物匹配最多使用2个只读计算线程，0/1个模板不创建线程池。
  每个模板的匹配阈值、NMS、
  搜索框扩边及返回坐标约定保持原 RuleImage 行为。线程不操作设备、
  不改 RuleImage ROI，单次计算结束即释放线程。
- 同一截图复用御魂匹配和手牌卡框；发现御魂、发现纹章、纹章共用
  一次手牌文字区OCR。商店摘要/刷新确认也只用当前阵容图片兜底，
  不为日志再做全式神图片扫描。全目录属性保留仅供显式诊断调用。
- 每回目首次确认进入备阶段且商店收起后识别一次整盘。后续以确认的动作更新棋盘，
  购买可能升星时只检查同名场上单位。手牌观察在同帧、同阶段、同回目
  的0.7秒内复用，动作前作废。不同截图的手牌及勾玉区域像素完全一致时，
  复用模板匹配和星级结果。动作确认仍采集新帧，卡面像素变化或换阵容会重新匹配。
- 只为实际受阻的上阵打开挡位详情。非阵容棋子在详情直接出售，
  避免先拖进手牌再处理。手牌普通式神的高置信勾玉可免去御魂和 OCR
  排除。已有两帧稳定卡面时只补一帧确认。
- 普通动作等待0.6→0.25秒，慢轮询1→0.35秒，快速轮询0.1→0.04秒。
  连续确认帧仍间隔0.35秒，满币、大厅稳定及固定阶段总超时保留。
  “鬼/待”空闲观察每1.05秒一次，待阶段经济仍在同一运营循环内连续执行。
- 普通拖动长按0.5→0.25秒，uiautomator2/ADB普通滑动0.5→0.16秒；
  minitouch按请求时长分配移动等待，终点等待280→40毫秒；scrcpy减少
  中间触点并缩短终点等待。上阵、回收、出售或御魂装配未确认时，
  后续普通长按恢复0.5秒兼容慢设备，仍需新截图确认后才能继续。

离线基准（2026-11-09）：用户提供的三阶64金币“待90”截图，预热后
各运行6次。反击姑获鸟只需8个人物模板（含河童），原全目录为59个。
原全目录8路匹配与现阵容2路匹配在此图均未匹配到式神手牌（仅有木魅）：
墙钟中位耗时79.7→27.2毫秒，进程CPU中位耗时578.1→54.7毫秒。
这仅是人物模板匹配环节，不代表整个脚本的CPU占用下降比例或整局提速；
截图传输、OCR服务、装备识别和游戏动画仍影响实际速度。

缺素材第三回合截图的模拟出售回放：确认链由10次截图缩至6次，固定
等待由约2秒缩至0.95秒；本次识别路径约0.51秒（不含等待/真实设备
截图及拖动），未调用御魂匹配。出售用桩模拟，不代表游戏内实测耗时。

图像漏匹配登记购买成功。未实测图像模式整店耗时，不能沿用旧 OCR 耗时作为收益。
