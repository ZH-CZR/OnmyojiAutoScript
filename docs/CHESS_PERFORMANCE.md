# 百鬼棋局操作提速

提速仅影响棋局任务，不改其他任务配置、不关闭设备卡死检测。

- 任务执行期间将设备截图最小间隔临时设为0.05秒；scrcpy沿用公共实现的
  0.1秒下限。正常退出、异常及闲时让位均在 finally 恢复原间隔快照。
- `runtime/performance.py` 按设备帧号与截图对象身份缓存纯识别结果，包含
  回目、阶段、阶数、倒计时、占位、勾玉星级和手牌。新截图立即失效；
  无帧号时不缓存。不会缓存动作允许状态或跳过交易后截图。
- 手牌人物匹配最多使用8个只读计算线程。每个模板的匹配阈值、NMS、
  搜索框扩边及返回坐标约定保持原 RuleImage 行为。线程不操作设备、
  不改 RuleImage ROI，单次计算结束即释放线程。
- 连续部署多个已确认手牌时，首轮核对整盘星级，随后仅移动到空位无需
  每张牌重新核对整盘。新一轮部署、购买及回收后仍重新核对。
- 普通动作等待0.6→0.25秒，慢轮询1→0.25秒，快速轮询0.1→0.04秒。
  连续确认帧仍间隔0.35秒，满币、大厅稳定及固定阶段总超时保留。
- 普通拖动长按0.5→0.25秒，uiautomator2/ADB普通滑动0.5→0.16秒；
  minitouch按请求时长分配移动等待，终点等待280→40毫秒；scrcpy减少
  中间触点并缩短终点等待。上阵、回收、出售或御魂装配未确认时，
  后续普通长按恢复0.5秒兼容慢设备，仍需新截图确认后才能继续。

离线基准：用户提供的26回合购买寻香行后的1280×720截图，59张手牌
模板预热后各运行6次。2026-11-09本机匹配中位耗时约400.7→92.5毫秒，
名称、位置及匹配分数一致。约4.3倍提升仅指该匹配环节，不代表整轮
操作或整局速度；截图传输、OCR服务和游戏动画仍影响实际速度。

验证使用 `dev_tools.test_chess_performance`、`dev_tools.test_chess_inventory`、
`dev_tools.test_chess_counter_ubume` 及原棋局 grigri/season/p0/shop/
runtime_safety/idle/exit、配置模板和任务/服务启动回归。
未启动游戏，短按识别、真实拖动成功率与整轮耗时仍待设备实测。
