# 百鬼棋局闲时目标

## 目标规则

| 目标 | 完成条件 |
| --- | --- |
| 每周目标 | 固定刷满鼬乐币，忽略执行次数和满币开关 |
| 每日目标 | 达到执行次数；开启“刷满鼬乐币”时也可由满币提前完成 |
| 本次目标 | 本次配置启动累计达到执行次数；开启“刷满鼬乐币”时也可由满币提前完成 |

每周为显式自然目标，不虚构数字上限。每日/本次正数 `run_count` 为目标局数；
`-1` 或零不提供有效次数上限，只有同时开启满币退出才具有自然完成条件，
否则不进入闲时队列。棋局没有新增运行时间目标。
未勾选满币退出的每日/本次目标不主动读取币数，沿用次数目标；已经保存的满币
停刷期限仍然生效，不能用关掉开关绕过。

## 满币后本周停刷

手动执行为例外：用户通过前端立即执行可绕过已保存的周停刷期限，原记录不清除；切回定时或闲时后仍继续生效，详见 `docs/MANUAL_EXECUTION.md`。

沿用现有鼬乐币 OCR 解析规则，在棋局大厅用间隔0.35秒的新截图连续两次确认
`600/600` 才标记满币。开局前已满币时不开新局，整局结算后满币时保留本局次数。
一次误识别、无效 OCR 或只识别出一帧满币都不能直接完成周目标。

一旦确认满币，不论当前是每日、每周、本次目标或定时执行，都将本配置的棋局
停刷期限保存到下周一本地00:00。其优先级高于目标类型、会话及原计划：

- 跨日、热重载、进程恢复、停止后再次启动配置不清除停刷期限。
- 改目标、关闭满币开关、切回定时、手动提前 next_run 均不能使调度器本周再选中棋局。
- 定时模式的有效下次时间取原计划与停刷期限的较晚者，不改写原计划作为占位。
- 下周截止后解除停刷限制，仍须满足所选目标资格（本次目标还须新会话）；
  再次获得执行资格时重新识别实际币数，不沿用上周的 OCR 结果。
- 数据按配置隔离，不以一个配置的满币状态阻止其他配置。

停刷期限存于忽略的 `config/activity/idle.sqlite3:task_blocks`，不写用户配置。
每日/本次仅次数达标时，仍按对应日或会话恢复资格，不自动延至下周。
周刷新边界沿用通用接口本地周一00:00，没有新增服务器时区配置。

## 整局计数与让位

入口先按原恢复逻辑退出遗留棋局或完成遗留结算，再进入大厅。
这些恢复退出不增加局数，也不抵扣待执行的保段位退出次数。
每次正常对局必须走实际游戏结束页与返回大厅流程；在新截图上确认大厅稳定
出现至少1秒、延迟奖励已处理后，才允许累计一次。
无名次 OCR 仍可按已确认整局计次，但不会触发“前四名”的保段位操作。
局内小回目、备/战/鬼/待阶段及主动退局均不作为完成次数。

保段位前四名触发的三次退出独立保存到 `task_state.rank_exits`。
成功退出一次才减一，不计入正常局数；恢复或切回定时后继续剩余次数，不能重新退三局。
达到目标或满币后立即停止，不为补足退局继续占用空档，剩余操作留给下一次具备
执行资格的片段；关闭保段位时不执行，但保留原剩余次数。

在大厅检查 X/Y、普通任务与目标状态，不在对局内部因调度时间强制退出。
确认返回庭院才交回调度；导航或结算失败走原异常处理。
保留原设备检测和既有棋局状态机，不新增关闭卡死检测的逻辑。
单局过长仍可能延后普通任务，用户按整局耗时设置余量。

满币检查最多三帧仍无法可靠判断时，不冒充满币：返回庭院、保留已完成局数，
冷却60秒再获得候选资格。公共 `IdleExecution.finish()` 会保留该冷却，不重置目标。

## 接口及验证

- `tasks/Chess/runtime/idle.py`：闲时整局编排、稳定满币及大厅判断、返回庭院。
- `tasks/Chess/config.py:idle_limits/idle_natural_goal`：次数及自然目标声明。
- `module/config/idle.py`：自然目标资格、独立任务停刷、任务私有进度、识别冷却。
- `module/config/config.py`：定时计划同样遵守棋局满币期限。
- 原定时模式保留次数与保段位循环，满币确认增强为两张新截图，并保存本周停刷。
