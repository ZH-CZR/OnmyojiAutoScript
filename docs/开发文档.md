## 1. 项目是什么

OAS（OnmyojiAutoScript）是一个面向《阴阳师》手游的自动化脚本框架，思路来自《碧蓝航线》脚本 Alas（AzurLaneAutoScript）。

它做的事情可以概括为一句话：

> 截图 → 识别画面元素（模板匹配 / OCR）→ 决定点哪里 → 点击 → 再截图，循环直到任务完成。

支撑这句话的，是一个完整的工程体系：

- **设备层**：连接安卓模拟器（ADB / uiautomator2 / minitouch / scrcpy / DroidCast）或 Windows 桌面客户端（窗口截图 + 窗口消息点击）。
- **识别层**：图片模板匹配 + OCR，独立成服务进程，脚本通过 RPC 调用。
- **任务层**：每个玩法一个目录，包含配置模型、资源定义、流程脚本。
- **调度层**：像 Linux crontab 一样，根据每个任务的 `next_run` 决定现在该跑谁。
- **配置层**：pydantic 模型 + JSON 文件，改动自动落盘。
- **服务层**：FastAPI 提供 HTTP/WebSocket 接口，给 GUI / Web 前端使用。
- **界面层**：仓库内 `module/gui` 是 PyQt/QML 桌面 GUI；Web 侧提供 API 和标注器页面。

### 1.1 它与 Alas 的主要差异

README 已总结，对开发最重要的是这几点：

| 差异 | 对开发的影响 |
| --- | --- |
| 前后端拆离 | 脚本进程与界面进程分离，通过 HTTP / zerorpc / 队列通信 |
| 新的 Assets 管理 | 资源统一由 `dev_tools/assets_extract.py` 从 JSON 生成 `assets.py` |
| pydantic 配置 | 所有任务配置都是 pydantic 模型，改动即校验 |
| 图像/OCR 服务化 | 匹配不在脚本进程里做，而是发到 22269 / 22268 服务 |
| 新的页面导航 | `tasks/GameUi` 用「页面图 + 最短路径」导航，替代硬编码点击链 |

## 2. 技术栈与运行环境

### 2.1 语言与依赖

- Python **3.10**（见 `requirements.txt`、README 徽章）。
- 主要第三方库：
  - `pydantic 2.x`：配置模型
  - `fastapi + uvicorn`：Web 服务
  - `zerorpc + pyzmq`：GUI ↔ 脚本进程 RPC
  - `opencv-python`：图像处理与模板匹配
  - `ppocr-onnx + onnxruntime`：OCR
  - `uiautomator2 + adbutils`：安卓控制
  - `pywin32`：Windows 窗口操作
  - `paho-mqtt`：多人组队（team_flow）通信
  - `onepush`：消息推送
- 完整依赖清单：[requirements.txt](../requirements.txt)；直接依赖：[requirements-in.txt](../requirements-in.txt)。

### 2.2 系统要求

- Windows 10/11（桌面客户端模式、窗口截图、模拟器窗口管理都依赖 Win32 API）。
- 推荐使用仓库自带的 `toolkit/` 便携环境（Python、Git、adb 都在里面）。
- 路径尽量**不要包含中文和空格**，否则 ADB / 子进程 / 资源路径容易出问题。

### 2.3 三个关键端口

| 端口 | 用途 | 配置位置 |
| --- | --- | --- |
| 22288 | Web 服务（FastAPI） | [config/deploy.yaml](../config/deploy.yaml) `WebuiPort` |
| 22268 | OCR 服务 | `deploy.yaml` `Ocr.OcrServerPort` |
| 22269 | 图像识别服务 | `deploy.yaml` `Image.ImageServerPort` |

> 同时运行两个 OAS 实例时，这三个端口会冲突。要么分机器，要么改端口（见第 13 章）。

## 3. 十分钟架构总览

```
┌─────────────────────────────────────────────────────────────────┐
│                         用户 / 前端                              │
│   桌面 GUI (module/gui, PyQt+QML)   |   Web/HTTP 客户端 (OASX 等) │
└───────────────┬───────────────────────────────┬─────────────────┘
                │ zerorpc / HTTP                 │ HTTP / WebSocket
┌───────────────▼───────────────────────────────▼─────────────────┐
│                     服务进程 (server.py)                         │
│  FastAPI: home/script/stats/income/screen/log/tool/flow/...       │
│  MainManager: 管理每个配置对应的 ScriptProcess                    │
│  端口 22288                                                      │
└───────────────┬─────────────────────────────────────────────────┘
                │ multiprocessing spawn（每个配置一个子进程）
┌───────────────▼─────────────────────────────────────────────────┐
│                   脚本进程 (script.py → Script.loop)             │
│  调度：Config.update_scheduler → pending/waiting → 执行任务       │
│  任务：动态加载 tasks/<Task>/script_task.py                       │
│  设备：Device（截图 / 点击 / 启动应用）                           │
└───────┬───────────────────────┬─────────────────────────────────┘
        │ RPC                   │ RPC
┌───────▼─────────┐   ┌─────────▼────────────┐
│ 图像服务 22269   │   │ OCR 服务 22268        │
│ 模板匹配/缓存    │   │ ppocr-onnx 文字识别   │
└─────────────────┘   └──────────────────────┘
        │
┌───────▼─────────────────────────────────────────────────────────┐
│ 模拟器（ADB/uiautomator2/scrcpy）或桌面客户端（窗口截图+消息）    │
└─────────────────────────────────────────────────────────────────┘
```

一次任务执行的极简时序：

```
Scheduler 选出任务
  → Script.run("Orochi")
    → 动态加载 tasks/Orochi/script_task.py 的 ScriptTask
      → ScriptTask.run()
        → self.goto_page(page_orochi)      # 页面导航
        → while 循环: self.screenshot()    # 截图
                       self.appear(I_XXX)  # 识别（RPC 到图像服务）
                       self.appear_then_click(I_XXX)  # 点击
        → self.set_next_run('Orochi')      # 安排下一次
        → raise TaskEnd                    # 正常结束
```

## 5. 启动链路：三个入口和一堆服务

### 5.1 三个入口

| 入口 | 文件 | 作用 |
| --- | --- | --- |
| 桌面 GUI | `gui.py` | 启动 PyQt/QML 界面，管理配置和脚本进程 |
| Web 服务 | `server.py` | 启动 FastAPI（uvicorn），提供 HTTP/WS 接口 |
| 脚本进程 | `script.py` | 运行调度循环，实际执行任务 |

实际使用中，通常是先启动 GUI 或 Web 服务，再由它们拉起一个或多个脚本进程。

### 5.2 GUI 启动时发生了什么

`deploy/launcher/oas-gui.bat`（发布包中为 `oas.exe`）的流程：

```
python -m deploy.installer      # 检查/安装依赖、Git、adb、uiautomator2
  → start /B pythonw gui.py     # 无控制台启动 GUI
```

`gui.py` 做了这些事：

1. 强制时区为 Asia/Shanghai（兼容 Python 3.10 的 Windows 写法）。
2. `ensure_image_server_ready()`、`ensure_ocr_server_ready()` 确保两个识别服务可用。
3. 创建 `FluentApp`。
4. 注入四个 QML 上下文对象（属性名小写）：
   - `add_config`（类 `Add`）：新增配置
   - `setting`（类 `Setting`）：设置
   - `process_manager`（类 `ProcessManager`）：脚本进程管理
   - `utils`（类 `Utils`）：杂项
5. 注册自定义 QML 类型 `PaintImage`、`RuleFile`（用于显示截图和规则文件）。
6. `app.run()`。

### 5.3 Web 服务启动时发生了什么

`server.py`：

1. 同样设置时区、拉起图像/OCR 服务。
2. `uvicorn.run("module.server.app:fastapi_app", host, port)`。
3. 默认 `host=0.0.0.0`、`port=22288`（来自 `deploy.yaml`）。

`module/server/app.py` 挂载了这些路由：

| 路由前缀 | 文件 | 负责 |
| --- | --- | --- |
| 首页/总览 | `home_router.py` | 首页数据 |
| 脚本/配置 | `script_router.py` | 配置增删改查、导入导出、启动停止实例 |
| 统计 | `stats_router.py` | 任务统计 |
| 收益 | `income_router.py` | 掉落/收益 |
| 截图 | `screen_router.py` | 实时截图 |
| 日志 | `log_router.py` | 日志查询与流 |
| 工具 | `tool_router.py` | 标注器相关接口 |
| 自定义流程 | `flow_router.py` | flow 的 CRUD 与运行 |
| 阵容 | `chesslineup_router.py` | 斗技/阵容工具 |

另外静态挂载了：

- `/tool/annotator/static` —— 标注器前端
- `/tool/chesslineup/static` —— 阵容工具前端

### 5.4 脚本进程如何被拉起

`module/server/main_manager.py`：

- 启动时扫描 `config/*.json`，为每个实例创建 `ScriptProcess`。
- `ScriptProcess.start()` 使用 `multiprocessing.get_context("spawn")` 创建子进程。
- 选择 `spawn` 是刻意为之：避免子进程继承主服务的 ZeroMQ context。
- 子进程通过 `Pipe`/`Queue` 把日志、状态、指标回传给主服务。

`ScriptProcess` 有四种状态：`INACTIVE`、`RUNNING`、`WARNING`、`UPDATING`（更新流程使用）。

### 5.5 脚本进程主循环

`script.py` 的 `Script.loop()`：

```
while True:
    task = self.get_next_task()          # 询问配置：下一个跑谁
    decision = self.runtime.prepare_task_execution(task)  # 运行前准备
    success = self.run(inflection.camelize(task))
    # 统计失败次数；连续 3 次失败 → 通知 + 可选关模拟器 + exit(1)
    # 成功 → 重新加载配置，继续
```

`Script.run(command)` 的关键一行：

```python
module_path = str(Path.cwd() / 'tasks' / command / 'script_task.py')
task_module = load_module('script_task', module_path)
task_module.ScriptTask(config=self.config, device=self.device).run()
```

> 这就是「任务目录必须叫大驼峰、必须有 `script_task.py`、类名必须叫 `ScriptTask`」的原因。

## 6. 核心概念

这一章是开发文档的重点。每个概念都给出：它是什么、代码在哪、怎么用、容易踩什么坑。

### 6.1 Atom：原子规则

目录：`module/atom/`

「原子」是最小的可识别/可操作单元。所有任务都靠拼装这些原子完成。

| 类 | 文件 | 代表什么 |
| --- | --- | --- |
| `RuleImage` | `atom/image.py` | 一张模板图 + 搜索区域 + 阈值 |
| `RuleClick` | `atom/click.py` | 屏幕上的一个点击坐标（可带随机偏移） |
| `RuleLongClick` | `atom/long_click.py` | 长按坐标 + 时长 |
| `RuleSwipe` | `atom/swipe.py` | 从 A 滑到 B |
| `RuleOcr` | `atom/ocr.py` | 一块文字区域 + 匹配模式 |
| `RuleList` | `atom/list.py` | 可滚动的列表（图片列表或文字列表） |
| `RuleAnimate` | `atom/animate.py` | 判断动画是否稳定 |
| `RuleGif` | `atom/gif.py` | 多帧动图匹配 |

#### RuleImage 详解

```python
RuleImage(
    roi_front=(279, 278, 47, 60),   # 模板图的 (x, y, w, h)
    roi_back=(57, 120, 293, 403),   # 在画面中搜索的 (x, y, w, h)
    threshold=0.8,                  # 相似度阈值
    method="Template matching",     # 匹配算法
    file="./tasks/Orochi/o/o_orochi.png",
)
```

- `roi_back` 必须**包含** `roi_front` 可能出现的所有位置；范围越大越慢。
- `threshold` 越低越容易误判，越高越容易漏判。常用 0.6～0.9。
- 支持四种方法：
  - `Template matching`：普通模板匹配（最常用）
  - `Masked template matching`：带掩码（模板同目录 `xxx_mask.png`）
  - `Multi-scale template matching`：多尺度，适配缩放
  - `Sift Flann`：特征点匹配，适合形变较大的图
- 桌面客户端模式有 2px 的 ROI 外扩容差（`DESKTOP_ROI_MATCH_PAD`），用于吸收 DPI 重采样误差。

匹配实际发生在**图像服务**里，`RuleImage.match()` 只是把规则序列化后发 RPC。

#### RuleOcr 的匹配模式

在 `BaseTask.ocr_appear()` 中可以看到五种模式：

| 模式 | 含义 |
| --- | --- |
| `Full` | 只要识别到非空文字就算命中 |
| `SINGLE` | 识别结果必须**完全等于** keyword |
| `DIGIT` | 识别结果转整数后等于 keyword |
| `DIGITCOUNTER` | 处理「1/10」这类计数文本 |
| `DURATION` | 时间格式（如 00:30:00）比较 |

> 坑：`SINGLE` 是严格相等。像「正在连接：000」这种带倒计时的横幅不能用 SINGLE，只能包含匹配（参考 `BaseTask._is_reconnecting`）。

### 6.2 Assets：资源体系

任务目录下通常有：

```
tasks/Orochi/
├─ assets.py     # 自动生成，不要手改
├─ o/            # 图片与 image.json（不同任务前缀不同）
│   ├─ image.json
│   └─ o_xxx.png
└─ res/
    ├─ ocr.json
    └─ list.json
```

`assets.py` 由 `dev_tools/assets_extract.py` 生成，文件头明确写着：

```python
# This file was automatically generated by ./dev_tools/assets_extract.py.
# Don't modify it manually.
```

生成逻辑：

- `image.json` → `RuleImage` 常量，命名 `I_<名字大写>`
- `ocr.json` → `RuleOcr` 常量，命名 `O_<名字大写>`
- `click.json` → `RuleClick` 常量，命名 `C_<名字大写>`
- `long_click.json` → `RuleLongClick` 常量，命名 `L_<名字大写>`
- `swipe.json` → `RuleSwipe`
- `list.json` → `RuleList` 常量，命名 `L_<名字大写>`

> 注意：`long_click` 和 `list` 共用 `L_` 前缀，同一个类里若两者重名会冲突，命名时要错开。

用法：

```python
from tasks.Orochi.assets import OrochiAssets

class ScriptTask(BaseTask, OrochiAssets):
    def run(self):
        if self.appear(self.I_OROCHI):
            ...
```

**不要在 assets.py 里手写新规则**，否则下次生成会被覆盖。要改资源：

1. 截图；
2. 用标注器或手写 JSON；
3. 运行 `python dev_tools/assets_extract.py` 重新生成；
4. 提交 JSON + 图片 + assets.py。

### 6.3 BaseTask：任务基类

文件：`tasks/base_task.py`

它继承了 `GlobalGameAssets` 和 `CostumeBase`，提供所有任务共用的能力。

#### 6.3.1 截图

```python
self.screenshot()          # 截图并处理突发弹窗（好友邀请、断线、重连）
self.maybe_screenshot()    # 有图就不截（省时间）
self.exist_image()         # 当前是否有图
```

`screenshot()` 不是简单截图，它会在返回前：

1. 处理「好友邀请」弹窗（按配置接受/拒绝/只接勾协）；
2. 处理「已断开游戏服务器」弹窗；
3. 处理「正在连接……」横幅（原地等待网络恢复）。

这解释了为什么任务代码里通常不需要单独写这些弹窗的处理。

#### 6.3.2 识别与点击

| 方法 | 作用 |
| --- | --- |
| `appear(target)` | 目标是否出现（支持 interval 节流） |
| `appear_then_click(target, action=None)` | 出现就点，默认点目标中心 |
| `wait_until_appear(target)` | 等待出现 |
| `wait_until_appear_then_click(target)` | 等待出现再点 |
| `wait_until_disappear(target)` | 等待消失 |
| `wait_until_stable(target)` | 等待连续多帧稳定 |
| `wait_until_pos_stable(target)` | 等待位置稳定（用于动画停止） |
| `click(rule)` | 点一个 RuleClick / RuleImage / RuleOcr |
| `swipe(rule)` | 执行滑动 |
| `ocr_appear(target)` | OCR 命中判断 |
| `ocr_appear_click(target)` | OCR 命中并点击 |
| `list_find(target, name)` | 在列表中滚动查找 |
| `list_appear_click(target)` | 列表查找并点击 |

#### 6.3.3 通用 UI 流程

| 方法 | 作用 |
| --- | --- |
| `ui_click(click, stop)` | 反复点击直到出现 stop |
| `ui_clicks(clicks, stop)` | 多个候选轮流点直到 stop |
| `ui_click_until_disappear(click)` | 点到一个元素消失 |
| `ui_get_reward(click_image)` | 点开奖励并等「获得奖励」结束 |
| `ui_reward_appear_click()` | 「获得奖励」出现就点 |

#### 6.3.4 安排下一次运行

```python
# 按 Scheduler 配置的间隔安排（成功/失败可不同）
self.set_next_run('Orochi', finish=True, success=True)

# 指定绝对时间
self.set_next_run('Orochi', target=datetime.now())

# 指定「明天 8 点」这类时间
self.custom_next_run('Orochi', custom_time=Time(hour=8, minute=0, second=0))
```

#### 6.3.5 任务必须用 TaskEnd 结束

任务正常完成的标志是抛出 `TaskEnd`：

```python
from module.exception import TaskEnd

raise TaskEnd
```

如果普通 `return`，调度器会认为任务还在继续或异常，行为不符合预期。参考 `tasks/Orochi/script_task.py` 末尾。

### 6.4 Page / Navigator：页面导航

目录：`tasks/GameUi/`

这是本项目最有价值的抽象之一。传统脚本写法是「点 A → 等 B → 点 C」，页面一改就全线崩溃。OAS 改成**页面图**：

- 一个 `Page` 代表游戏里的一个稳定画面；
- `Page.connect()` 声明「从 A 页面做什么动作能到 B 页面」；
- `goto_page(destination)` 自动用最短路径（Dijkstra）走过去。

#### 定义页面

```python
from tasks.GameUi.page_definition import Page

page_orochi = Page(
    OrochiAssets.I_OROCHI_CHECK_10,  # 识别条件：看到这个图标就是御魂页
    priority=50,                      # 1-100，越大越优先
    cost=1.0,                         # 进入该页的代价
)
```

#### 定义边

```python
page_orochi.connect(
    page_exploration,                 # 目标页面
    GlobalGameAssets.I_UI_BACK_YELLOW,  # 动作：点返回
    key="page_orochi->page_exploration",
)
```

#### 导航

```python
self.goto_page(page_main)     # 自动找路并执行
self.get_current_page()       # 当前在哪
self.detect_page_in('page_main', 'page_reward')  # 判断是否在其中
```

#### 开发要点

1. **页面识别条件要唯一且稳定**。优先复用任务原本就会等待的特征。
2. 一条边只做一件事（点一次按钮）。
3. 如果页面有多个入口，用 `any_of(...)` 组合识别条件。
4. 新增页面后，检查它是否与已有页面冲突（优先级、识别条件）。
5. `Page` 构造时默认会注册到全局 `PageRegistry`；动态页面传 `register=False`。

```python
from tasks.MyTask.assets import MyTaskAssets
from tasks.MyTask.config import MyTask

class ScriptTask(BaseTask, GameUi, MyTaskAssets):
```

### 6.7 Config：配置系统

#### 6.7.1 三层结构

```
ConfigModel（整份 JSON）
 └─ 任务模型（如 Orochi）
     ├─ scheduler（调度器）
     ├─ xxx_config（玩法参数）
     └─ 复用组件配置（如 general_battle_config）
```

#### 6.7.2 任务配置模型

```python
from pydantic import Field

from tasks.Component.config_scheduler import Scheduler
```

### 6.8 Scheduler：调度器

文件：`tasks/Component/config_scheduler.py`

| 字段 | 含义 |
| --- | --- |
| `enable` | 是否启用 |
| `next_run` | 下次运行时间 |
| `priority` | 优先级 |
| `success_interval` | 成功后间隔（TimeDelta） |
| `failure_interval` | 失败后间隔 |
| `server_update` | 服务器维护时刻（用于避开维护） |
| `delay_date` | 延迟天数 |
| `float_time` | 随机浮动时间 |

调度流程（`module/config/config.py`）：

1. `Config.update_scheduler()` 遍历所有启用任务；
2. `next_run` 已到期的进 `pending_task`，未到期的进 `waiting_task`；
3. `pending_task` 交给 `TaskScheduler.schedule(schedule_rule, pending)` 排序；
4. 正在运行的任务不会被新任务顶掉（会被插到 pending 队首）；
5. 没有 pending 时，取 `waiting_task` 最早的一个作为「下一个」，然后 main loop 等待。

`schedule_rule`（默认 `Filter`）决定同一时刻多个任务到期时的排序策略。

### 6.12 异常体系

文件：`module/exception.py`

| 异常 | 含义 | 调度器默认处理 |
| --- | --- | --- |
| `TaskEnd` | 任务正常结束 | 视为成功，继续下一个 |
| `EmulatorNotRunningError` | 模拟器没启动 | 按设备设置尝试启动或报错 |
| `GameNotRunningError` | 游戏没启动 | 排一个 `Restart`，计失败 |
| `GameStuckError` | 画面卡住 | 存错误现场、重启、等 10s |

| `GameBugError` | 游戏本身 bug | 重启 |
| `GamePageUnknownError` | 未知页面（可能维护/断网） | 维护窗口内延迟任务，否则重启 |

`Device.handle_control_check()` 会检查：

- 同一位置短时间内点击次数是否过多；
- 是否长时间没有有效画面变化。

超过阈值就抛 `GameTooManyClickError` / `GameStuckError`。这是防止脚本在错误画面上疯狂点击的保护。

## 7. 任务调度与异常处理机制

### 7.1 一次调度的完整链路

```
Config.update_scheduler()
  ├─ 遍历 config_model 的每个任务字段
  ├─ Function(key, data) 提取 enable/next_run/priority
  ├─ next_run < now → pending
  └─ 否则 → waiting
        ↓
TaskScheduler.schedule(schedule_rule, pending)
        ↓
Config.get_next()
  ├─ 有 pending → 取队首
  └─ 无 pending → 取 waiting 最早（仅用于计算等待时间）
        ↓
Script.get_next_task()
  ├─ 反作弊/维护窗口调整
  ├─ 任务囤积（task_hoarding_duration）
  ├─ 等待到 next_run
  └─ 返回任务名
        ↓
Script.run(task)
  ├─ 截图
  ├─ 动态加载 tasks/<Task>/script_task.py
  └─ ScriptTask(...).run()
```

### 7.2 任务囤积（task hoarding）

`script.optimization.task_hoarding_duration` 大于 0 时：

- 空闲后第一个到期任务会被延迟最多 N 分钟；
- 延迟窗口内到期的其他任务会一起等待；
- 窗口结束后一起执行。

目的：避免任务零散触发导致模拟器频繁启动/关闭。

### 7.3 失败计数与三次失败

`Script.loop()` 中：

```python
failed = 0 if success else failed + 1
self.failure_record[task] = failed
if failed >= 3:
    # 推送通知
    # error_repeated=True 时关闭模拟器
    exit(1)
```

注意：`GameNotRunningError` 必须返回「失败」，否则无限重启的兜底会失效（代码注释写得很清楚）。

### 7.4 维护窗口

`tasks/Restart/server_update.py` 提供：

- `is_server_update_window()`
- `delay_pending_tasks_for_server_update()`

`GamePageUnknownError` 发生在维护窗口内时，会推迟任务而不是重启。

```python
from tasks.MyTask.assets import MyTaskAssets
from tasks.MyTask.config import MyTask, Mode

        self.goto_page(page_my_task)

        while count < config.my_task_config.limit_count:

            if config.my_task_config.mode == Mode.HARD:

                count += 1
                continue

                logger.info('finished')
                break

        self.goto_page(page_main)
```

`image.json` 每一项大致包含：

| 字段 | 含义 |
| --- | --- |
| `itemName` | 规则名（生成后加 `I_` 前缀并大写） |
| `description` | 注释（生成到 assets.py） |
| `roiFront` | `[x, y, w, h]` 模板区域 |
| `roiBack` | `[x, y, w, h]` 搜索区域 |
| `threshold` | 阈值 |
| `method` | 匹配方法 |
| `imageName` | 图片文件名 |

### 9.2 命名约定

- 图片文件：`<前缀>_<语义>.png`，例如 `o_orochi_fire.png`
- 规则名：生成后 `I_OROCHI_FIRE`
- OCR：`o_test_ocr` → `O_TEST_OCR`
- 点击：`c_random_right` → `C_RANDOM_RIGHT`
- 列表：`l_layer_list` → `L_LAYER_LIST`

### 9.3 生成命令

```powershell
python dev_tools/assets_extract.py
```

常见配套工具（`dev_tools/`）：

| 工具 | 用途 |
| --- | --- |
| `assets_extract.py` | 由 JSON 生成 assets.py |
| `assets_test.py` | 批量测试资源命中情况 |
| `get_images.py` | 从截图批量裁剪 |
| `template_update.py` | 模板图更新 |
| `bind_desktop_window.py` | 桌面窗口绑定调试 |
| `upstream_sync*.py` | 上游同步（与玩法开发无关） |

### 9.4 阈值经验

- 静态按钮：0.8～0.9
- 会变化的图标/带数字的按钮：0.6～0.75
- 半透明/动画：0.5～0.65，并配合 `wait_until_stable`
- 宁可多截几张不同状态做多模板，也不要盲目降阈值

## 10. 调试与日志

### 10.1 日志位置

- 运行日志：`log/`
- 错误现场：`log/error/<脚本名>_<时间戳>/`
  - `*.png`：最近若干张截图
  - `log.txt`：出错前后的日志片段
  - `diagnosis.json`：中文诊断包（错误结论、建议、时间线、环境、配置快照）
- 结构化运行日志：`log/runs/`
  - `YYYY-MM-DD/<run_id>.jsonl`：单次任务执行的 start / event / end 事件流
  - `index.jsonl`：每个 run 一行摘要，供列表与统计使用
- 保留策略（`module/logger.py` 的 `cleanup_logs` 在启动和每天第一次任务时执行）：
  - 文本日志 7 天；`log/error` 3 天；`log/runs/<日期>` 3 天；`index.jsonl` 7 天。

### 10.2 日志格式

```
2026-11-23 10:00:00.123 |            script.py:0450 |     INFO | Scheduler: Start task `Orochi`
```

- 时间 | 文件:行号 | 级别 | 消息
- 分隔线 `logger.hr(...)` 用于在日志里划出任务边界，`save_error_log` 会从最后一个分隔线截取。

### 10.3 常用调试手段

1. **前台跑脚本进程**

```powershell
python script.py
```

> `script.py` 的 `__main__` 里写死了配置名，先按实际实例修改；日常调试更推荐直接从 GUI/Web 启动，再观察日志。

2. **只测识别**

```python
from module.config.config import Config
from module.device.device import Device
from tasks.Orochi.assets import OrochiAssets

c = Config('oas1')
d = Device(c)
d.screenshot()
print(OrochiAssets.I_OROCHI.match(d.image), OrochiAssets.I_OROCHI.last_score)
```

3. **看实时画面**：Web 端 `/screen` 接口或 GUI 的预览。
4. **看错误现场**：先看 `log/error/.../log.txt`，再看最后一张截图。
5. **调阈值**：临时把 `threshold` 改低，确认是识别问题还是流程问题；确认后恢复并优化 ROI。

### 10.4 断点调试

- 在 VS Code 里用 `debugpy` 附加到 `script.py` 进程；或
- 直接 `python script.py` 前台运行（注意配置名写死在 `__main__` 里，需要改）。
- Windows 下用 `toolkit\python.exe` 保证依赖一致。

### 10.5 结构化运行日志（run / JSONL / 诊断包）

代码在 `module/log/`，由 `script.py` 在任务开始和结束时调用：

| 文件 | 作用 |
| --- | --- |
| `module/log/run_context.py` | run 上下文（contextvars），自动携带 `config_name / task / run_id / attempt` |
| `module/log/run_store.py` | JSONL 追加、索引、24h 统计、过期清理 |
| `module/log/error_codes.py` | 异常 → 中文错误码（结论 + 建议） |
| `module/log/diagnosis.py` | 在错误目录生成不超过 64KB 的 `diagnosis.json` |

约定：

- 一次任务执行尝试 = 一个 run；失败重试时 `attempt` 递增，`parent_run_id` 指向首轮。
- 原有 `logger.info/warning/error` 调用不用改：`module/logger.py` 里的 `RunLogHandler` 会把 WARNING 及以上自动写进当前 run。
- 出错时 `save_error_log()` 除了截图和 `log.txt`，还会生成 `diagnosis.json`，并把目录名记进索引。
- 对外接口见 [logging-api.md](./logging-api.md)（给 OASX 的请求/响应、错误码表、统计口径）。
- 单测：`toolkit\python.exe -m pytest tests\test_log_runs.py -q`。

## 11. 测试体系

### 11.1 目录

```
tests/
├─ test_*.py     # 目前主要测试都在顶层
├─ module/       # 预留/历史目录（当前仅剩 __pycache__）
└─ tasks/        # 预留/历史目录（当前仅剩 __pycache__）
```

顶层测试大致覆盖：原子规则（点击、模板匹配）、断线重连守卫、通用战斗、任务逻辑（斗技、年兽、悬赏等）、flow 的 schema/runtime/codegen/store、上游批次回归。

### 11.2 运行

```powershell
python -m pytest tests -q
```

如果 `toolkit` 环境没有 pytest：

```powershell
python -m pip install pytest
```

### 11.3 测试风格

现有测试大量使用「构造最小对象 + mock」的方式，不连真机。例如：

- `test_rule_click_humanize.py`：验证拟人点击落点分布；
- `test_reconnect_guard.py`：验证断线重连保护；
- `test_flow_*.py`：验证流程 schema/runtime/codegen；
- `test_shared_ui_assets.py`：验证共享 UI 资源约束。

### 11.4 写测试的建议

1. 纯逻辑（时间计算、配置解析、识别结果判定）优先写单测。
2. 涉及截图/点击的，用 mock 替代 `device.screenshot()` / `device.click()`。
3. 不要写依赖真实模拟器的测试进 `tests/`（会拖慢且不稳定）。
4. 修 bug 时先补一个能复现的测试，再改代码。

## 13. 常见开发坑

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 识别率突然下降 | 分辨率/DPI 变化，roi_back 贴边 | 开大 roi_back，桌面模式确认 2px pad |
| 点到了但没反应 | 动画未结束 | 用 `wait_until_stable` / `wait_until_pos_stable` |
| `GameTooManyClickError` | 死循环点同一处 | 在循环里加状态判断，避免盲点 |
| 任务跑完不结束 | 忘了 `raise TaskEnd` | 补上 |
| 配置改了没生效 | 改的是缓存模型但没触发 setattr | 用 `config.set_arg()` 或直接改字段 |
| 新增任务菜单不显示 | 没注册 `config_menu.py` | 补菜单分组 |
| 新增任务调度报错 | 没注册 `config_model.py` | 补字段与 import |
| assets.py 被覆盖 | 手改了生成文件 | 改 JSON 后重新生成 |
| 子进程起不来 | 端口被占用 / 路径含中文 | 换端口、规范路径 |
| 中文乱码 | 子进程编码 | 注入 `PYTHONIOENCODING=utf-8` |
| Git 拉取失败 | 直连 GitHub 不通 | 使用项目脚本的代理探测，不要改 git config |

## 14. 术语表

| 术语 | 含义 |
| --- | --- |
| Atom / 原子 | 最小的识别或操作单元 |
