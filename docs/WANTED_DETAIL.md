## 原有悬赏黑名单

在“悬赏封印 → 悬赏封印 → 悬赏黑名单”填写完整名称，例如 `青蛙瓷器`。多个名称用中文/英文逗号、顿号、分号或换行分隔，例如 `青蛙瓷器，山兔`。沿用原配置字段 `wanted_quests.wanted_quests_config.unwanted_boss_names` 与原前端帮助键 `unwanted_boss_name_help`，默认空字符串。已有黑名单原样读取、保存，不另设跳过功能或迁移黑名单。

黑名单沿用现有文本输入、任务参数接口与保存流程；前后端显示名统一为“悬赏黑名单”。更新后重新打开前端，并重启后端加载配置定义；本次不修改用户实际黑名单。

每次进入详情，先读取顶部“悬赏目标：击败N个妖怪名”，以完整名称精确匹配黑名单，不按片段或模糊匹配。命中黑名单后：

1. 点击详情右下角“取消追踪”。
2. 确认该位置出现“追踪”且“取消追踪”不再存在，才视为取消成功；漏识别或过渡帧不能代替正向确认。
3. 点击右上角叉号，确认详情消失并返回探索。
4. 从探索左列第一项重新识别，处理取消后任务上移，继续其他悬赏。

已处于“追踪”状态时只关闭详情，不反向点击重新追踪。名称无法识别时，启用了黑名单就抛出 `GameStuckError`，不猜测名称、不战斗也不取消其他任务。黑名单为空时无需名称 OCR。

- 详情身份改用“悬赏目标”标题，移除旧小追踪复选框作为详情识别/退出依据。
- 四行“前往”按钮及类型、关卡描述 OCR 坐标更新；只处理完整显示且检测到按钮的行。
- 顶部左侧独立数字是式神挑战券余额，使用 `Digit` 读取区域 `(548,12,106,34)`；截图中的余额为 `3876`。右侧 `2/30` 是突破券，不参与悬赏选路。每次详情按新截图重读挑战券余额，识别失败按 0 处理。
