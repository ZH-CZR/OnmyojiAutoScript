# 六道之门闲时适配

## 执行与目标

在六道之门调度器选择“闲时执行”，选择每日、每周或本次目标，设置 X/Y，
使用原有 `six_realms_gate.limit_count` 与 `limit_time` 作为累计目标。
任意有效上限达到即停止，零表示该项不限；两项都为零时不进入闲时队列。
默认模式仍是定时执行。

椒图、觉都以**完整结束一整局**为一次，包含失败后收尾的整局；
不是成功通关次数，不按岛屿战斗、宝箱、经验奖励或小关结算计数。
`one()` 的原布尔返回值保留，新增 `round_result` 区分未开局、门票不足、
整局结束与失败结算。未确认结算、识别或导航异常不会增加局数。

**按用户要求：椒图开启“是否只打门票”后，识别到门票不足即视为当前闲时目标完成。**
不增加局数，已经完成的局数保留，返回庭院后停止本周期的六道任务：

- 每日目标等次日本地零点刷新。
- 每周目标等下周一本地零点刷新。
- 本次目标等用户成功停止配置并再次启动后重置。

关闭“只打门票”时保留原来的执行方式，不额外检查门票。
觉原本没有门票检查，仍不宣称支持该开关；此适配没有新增觉的门票 OCR。

## 安全让位

普通已到期任务优先，距离下一普通任务严格超过 Y 分钟时开始/恢复。
执行准备结束及每局最终奖励处理完后调用通用闲时检查点；不会在岛屿间或战斗中退出。
整局次数或累计运行时间达标、普通任务到期、剩余时间 <= X、目标周期或模式变化时，
先通过现有公共导航返回庭院，并用新截图确认庭院，才抛出 `IdleYield` 交回调度。
修改六道类型时同样在整局边界退出，下一片段重建对应类型。

椒图和觉均在最终退出按钮处理后，继续处理延迟出现的奖励、经验及结束界面，
等待准备按钮在新截图中稳定出现至少1秒，再确认整局完成；结算点击及稳定确认
各最多等待15秒，失败抛出 `GameStuckError`，不计局数，不伪造返回庭院成功。
未关闭设备卡死检测。原来的子任务继续共享调度器绑定的设备。

时间是累计实际执行时间，不含调度让位等待或公共运行守卫休息。
时限在安全检查点生效，所以最后一局可以超过设定时间；不会预测单局耗时。
用户应按**整局**的可能耗时设置 X/Y，单局过长仍可能推迟下一普通任务。

本次不新增岛屿级暂停或局内技能状态持久化；游戏异常退出后的续局仍沿用原逻辑，
不保证恢复出事前的技能统计。没有改动素材、庭院路径、门票消耗方式或私人授权模块。

## 旧定时模式与接口位置

- `tasks/SixRealms/script_task.py`：入口按运行上下文分流，定时流程继续使用旧
  `saved_count` 与下周一安排；闲时流程独立累计，不写旧次数，不调用每周调度。
- 六道的旧进度保存原来依赖不存在的 `Config.safe_save()`，本次在六道任务内
  改用现有 `lock_config`、`reload()`、`save()`，保留定时中断恢复语义。
- `tasks/SixRealms/settlement.py`：两个类型共用的整局结果和闲时结算稳定确认；
  定时模式保留原点击路径，不额外引入等待。
- `tasks/SixRealms/config.py:idle_limits()` 与 `module/config/idle.py:ADAPTERS`：
  注册原有次数和时间上限。公共 `yield_task()` 共用返回庭院及让位状态记录。

前端直接使用此前新增的模式、目标与总览接口，无需再次构建。
重启后端后可识别新的六道适配器；不自动启用任务或修改用户配置。
