# 手动执行与奖励后让位

`execution_mode` 有定时执行（默认）、闲时执行、手动执行。手动任务需启用，且仅前端“立即执行”或“全部立即执行”提交一次性请求才运行；启动配置、修改旧时间、task_call/task_delay 均不会自动启动手动任务。停止配置时可先排队，启动后执行。

仅选择手动执行的任务拥有最高优先级。`POST /{script}/{task}/run_now` 对手动模式写入忽略的 `config/activity/manual.sqlite3`，按配置隔离并按点击顺序执行，排队重复点击合并，运行前原子消费令牌。定时模式仍只把本任务 next_run 设为过去，按原排序等待，不进入最高优先队列、不触发奖励后抢占。模式切换或禁用后清理失效请求；显式停止、删除及重命名配置清理请求。

手动模式隐藏无效的调度时间、间隔、优先级、随机延迟、闲时目标及任务专用时间参数，但保留原值。总览持续显示未触发的手动任务，保留“立即执行”“立即等待”。手动“立即等待”只撤销本任务未开始的请求，不调用 task_delay、不重载/保存配置，不改其他任务或当前运行任务；省略 target_dt 也有效。定时“立即等待”沿用原有排期规则。无效任务返回失败，不误报成功。

## 寮突破暂停恢复

按用户指定，寮突破已接入奖励后的安全让位。战斗中只等待；明确识别奖励并完成原领奖流程后，连续新截图确认寮突列表稳定1秒，且次数/时间目标尚有剩余，才调用 immediate_checkpoint。胜败页、偶然返回列表或任意截图均不能伪造领奖完成。次数已够或时间已到时正常结束，再调度手动请求。

`module/script/immediate.py` 保留寮突破同一个实例与原 Python 调用栈，确认退出并返回庭院后暂停，按顺序执行待处理的手动请求。手动任务完成后重新进入寮突破、恢复其御魂及锁队配置，继续原调用位置；当前次数和局部进度不清零，不重新调用 run。暂停耗时从寮突运行时限扣除，独立任务耗时仍正常记账。进入新列表后区域索引回到0，按新截图检查当前区域，避免继续点旧坐标。卡死检测始终保留。

同为最高优先级的新请求不会递归打断当前手动任务，按点击顺序继续执行；处理完后恢复寮突。用户在暂停期间禁用寮突或修改其模式则取消恢复。立即等待可在准备阶段撤销尚未消费的请求。导航/恢复失败走原异常机制，不声称已经安全返回；停止进程会结束保留的调用栈，不承诺跨服务重启恢复。

这是寮突破的任务专用接入，不是全部任务的任意截图抢占。其他未接入任务继续原运行流程；闲时任务仍使用其原有显式领奖检查点及清理接口。

## 总览与验证

暂停任务保留在标准 pending 队列中（手动请求之后、普通待执行任务之前），同时提供 suspended 状态与次数；让位时固定保存原 next_run，刷新不重新生成。前端合并同名元数据，只显示一个橙色待恢复条目，恢复后回到运行行。没有暂停元数据支持的客户端也能通过标准队列保留该任务。

总览区分 active_task（实际运行）与下一候选，排队的手动任务仍能点击立即等待。suspended 列表显示“已暂停，等待手动任务完成”和次数。暂停快照通过进程队列同步，服务端仅接收当前任务子进程PID的快照，停止/异常时清理，不写用户配置。前端单项操作显示成功或失败，避免失败时无反馈。

历史配置中的 running_task 不作为实际运行依据：新建 Config 清空旧标记，任务进程重载保留内存中的实际任务；开始、结束及让位时上报带当前PID的运行快照，服务端总览只使用该进程快照，停止/异常时清空。未启动的道馆等手动任务撤销请求后显示等待手动执行。百鬼棋局等闲时候选显示目标与进度，不把每次刷新生成的调度唤醒时间显示为任务计划。

`running_task` 为仅内存字段，赋值不保存配置，序列化也排除此字段；因此初始化清空、总览回填和让位恢复不会意外写回整份配置或触发配置文件重载。

离线验证：dev_tools.test_immediate_preemption、dev_tools.test_manual_schedule、现有调度/闲时/活动守卫/启动回归，另运行 dev_tools/check_i18n.py 与 pip check。前端 args、idle_args、manual_api 测试及 flutter analyze。未启动设备、OCR或游戏操作，离线模拟不等于游戏实测。
