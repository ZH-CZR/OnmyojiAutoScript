# 百鬼棋局商店确认

棋局商店使用独立的 `I_CHESS_SHOP_REFRESH`，不可使用 `self.I_REFRESH`：
完整任务继承链会将后者解析为 `GameUiAssets` 的公共导航刷新图标，
导致商店虽然展开却持续报告按钮缺失，经济序列停在刷新步骤，金币不断积累。
回归必须通过完整 `ScriptTask` 检查素材解析，不能仅测试 `ChessAssets`。

经济循环中每组买经验执行两次，每次仍花费 4 金币并单独检查预算、阶段及时间。
1～2 阶只买经验；3～7 阶按“经验、经验、刷新”循环；8 阶起未达目标时
按“经验、经验、刷新、刷新”循环。达到阵容目标阶数后只刷新。
升级改变阶数时按新阶数重置序列；预算或时间不足可在两次经验之间停止。
保留金币仍为 1～2 阶 0、3～5 阶 35、6～7 阶 23、更高未达目标时 10，
达到目标后为 0。

备阶段先购买现有阵容卡，经济循环在剩余15秒时让出时间完成上阵与装备。
两项完成后再次运行经济循环，直到剩余3秒停止，不重复上阵或装备。
续跑仍检查备阶段、符咒弹窗、金币预算与商店状态；战阶段剩余5秒时停止新操作。

战阶段临时开店失败、按钮遮挡或 OCR 失败返回 blocked，不再视为本回目经济完成。
外层每隔至少3秒重试，并重新读取回目和阶段；预算耗尽或剩余5秒及以内才标为完成。
首次购买同样使用战阶段开店确认，未确认展开时不扫描卡片或刷新。

战阶段不能仅凭 `_shop_assumed_open` 或点击商店成功返回就继续读卡、刷新。
`I_CHECK_MARKET` 在商店收起时也可能出现，不作为展开确认。
开店以刷新按钮或金币不足刷新标志为准；战阶段先等待一张新截图，
若仍未确认则只点击一次商店，并在最多 8 秒内等待展开标志。
超时或阶段切换后停止当前购买和刷新，避免反复开关。

备、战阶段的刷新均要求当前帧可见可用刷新按钮，不能因战斗特效遮挡而盲点。
刷新按钮短暂不可见时最多检查3帧（间隔0.35秒），恢复后才允许点击；
持续失败记录阶段和模板分数，鬼阶段中断单独记录，不再误报为按钮缺失。
刷新后商店不可见时不扫描棋盘区域；买卡后商店不可见时，不能把卡片消失当作购买成功。
保留原设备卡死检测，未改变刷新坐标、经济预算或闲时目标。

P0 交易保护（2026-10-28）：每次刷新只点击一次，在同一回合、同一阶段以
两张稳定新帧及扣款或任意槽位变化确认。不再要求至少三格变化；结果未明时
本局停止付费刷新（开新局才清除保护），防止外层重试再次扣款。
全同名回刷需要扣款证据；仅扣款而画面不稳定也不能开始买卡。

购买未确认先等待动画，再尝试安全清理；紧急清理保留未知卡及所有阵容材料。
清理后仍受阻则停止本轮购买和刷新，不出售最右阵容卡。战阶段清理按战阶段
关闭商店，只允许清理，不执行备阶段装备动作。星级持有上限与达标后的
多余卡清理见 `CHESS_INVENTORY.md`；完整买卖价值比较仍待后续优化。

离线回归：`dev_tools.test_chess_p0` 覆盖重复站位、同名/少量变化刷新、动画、
跨回合、结果未明锁定、买卡延迟、阵容保护、战阶段清理及占位冲突。
`dev_tools.test_chess_shop` 使用模拟帧覆盖旧缓存、辅助图标误判、
开店失败、延迟展开、技能短暂遮挡、阶段变化及购买/刷新后收店，不操作游戏。
配合 `dev_tools.test_chess_idle`、`dev_tools.test_task_startup` 和
`dev_tools.test_server_startup` 验证；离线通过不代表游戏实测通过。
