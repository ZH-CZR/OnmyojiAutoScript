# 配置文件与运行实例生命周期

配置复制、重命名、删除使用共享名称校验，拒绝空名称、点、路径分隔符、控制字符以及保留模板名称。模板可以作为复制来源，不能作为复制目标、重命名来源/目标或删除目标。最终路径解析后仍须位于 config 目录，阻止符号链接指向目录外的文件。

重命名、删除入口在停止任务前校验名称、来源和目标。运行实例标记 retiring 后拒绝再次启动；等待 stop 完成，再修改文件并移除管理记录。重复操作返回 409。停止或文件操作失败时保留实例记录并解除 retiring，避免仍存活的任务失去管理入口。stop 在终止子进程后在线程中等待退出，最多 10 秒；超时保留进程引用和原状态并报告错误，不伪报停止成功。

后台推送每轮按当前配置实例的身份整理日志/状态协程。配置移除、同名替换时取消旧协程并等待清理，为新实例创建推送协程；意外结束的协程也可重建。数据线程退出时清理其持有的全部协程。此改动不调整前端 WebSocket 重连策略。

启动期间显示准备状态，只有当前子进程完成日志和 Script 初始化、上报带PID的就绪消息后才报告运行中；启动调用失败、初始化异常或调度循环退出均推送警告和原因。后台每轮及 WebSocket 查询检查进程是否存活，退出时清理运行/暂停/启动排序快照，不改任务计划、不消费或清空尚未执行的手动请求，也不自动重跑已消费请求。前端绿色仅代表任务实际开始，排队保持橙色；错误消息在前端提示并写入服务日志。

再次启动配置时重建队列和日志管道，关闭旧IPC，避免强制终止的写入方留下损坏队列、锁或过期就绪消息。初始化前的日志配置错误也经状态队列回传；旧子进程PID的就绪消息不得改变新实例状态。

启动与停止共用跨线程互斥锁，等待锁时不阻塞事件循环。停止请求先取消已经在途的启动，再等待其退出临界区；即使启动正在等待状态广播，也不能在停止成功后继续创建子进程。停止中的新启动请求等待旧进程退出后才创建新进程。启动内部替换旧进程使用已持锁的停止流程，避免重入死锁。

`running_task` 赋值只改变内存，不触发自动保存，也不参与配置序列化。旧字段仍可读取以兼容旧配置，但 Config 初始化会清空它，运行中重载保留当前内存值。查询、总览刷新及任务开始/结束均不得因更新此标记而写盘；正常配置字段保存继续生效。

实时日志使用 `module/server/worker_log.py` 的独立守护发送线程及256条有界缓冲。管道堵塞时任务线程不等待，缓冲满时丢弃较旧的实时日志；文件日志继续独立记录。进程退出最多等待实时日志线程0.5秒，不因监控管道卡住退出。WebSocket 每个客户端独立发送，发送（含等待该连接发送锁）最多2秒，关闭握手最多0.5秒；慢连接移除后不影响其他客户端。后台推送转交连接所属的 HTTP 事件循环执行，同一连接的状态和日志串行发送。此改动不调整前端重连策略。
